Security

Last updated: November 4, 2026 · Version 1.0

Orchy is built so that your work stays on your own computer. This page explains how that works, what we protect, where the limits are, and how to report a security problem.

We hold no security certifications for Orchy (such as SOC 2 or ISO 27001). This page describes what the software does, not an audit.

1. Local first

  • The Orchy app runs on your computer. Its dashboard listens only on your own machine (127.0.0.1), so other devices on your network can't open it.
  • Orchy does not send your tasks, files, keys or logs to us. There is no telemetry.
  • Data leaves your computer only when you connect a service yourself (your AI engine, a routing provider, One, voice providers, Cloudflare). It goes straight from your computer to that service, under your own account.

2. Who can control your Orchy

  • Paired browsers only. A browser must be paired with a one-time code before it can change anything. Any change request must come from a paired browser and carry that browser's key.
  • Approval gate. Before an agent sends a message, spends money, changes a calendar, deletes something or shares something, Orchy asks you to approve it.
  • Separate accounts. Each workspace uses its own logins for connected apps. Accounts are never mixed between workspaces.

3. Secrets

  • The API keys you enter are stored in a settings file (.env) on your computer. They are not encrypted by Orchy. Protect your computer with a login password and disk encryption.
  • Login tokens for remote tool servers (MCP) are stored in a file only your user account can read.

4. Client pages (optional)

If you turn on client pages, they run on a separate port and are reached through Cloudflare Tunnel, with Cloudflare Access checking each visitor's identity first. The main dashboard is never exposed this way.

5. Our website

  • imorchy.dev is served over HTTPS only. Plain HTTP requests are redirected to HTTPS, and browsers are told to use HTTPS for a year (HSTS).
  • A strict Content Security Policy lets pages load code only from imorchy.dev. The one exception is a 3D graphics library loaded from jsDelivr on the home page.
  • The site sets no cookies of its own, has no login and runs no analytics.
  • Other protections: no framing by other sites, no MIME sniffing, a strict referrer policy, and camera, microphone and location access turned off.

6. How we build Orchy

  • Every change goes through a pull request.
  • Each pull request is checked by a QA and security reviewer and then reviewed again before it can be merged.
  • Each pull request is scanned for leaked secrets before review.
  • Automated tests run on each pull request, on Windows and Linux.

7. Known limits

We'd rather be clear about what Orchy can't protect against:

  • The approval gate is a filter, not a sandbox. Agents run with your user account's permissions.
  • If your AI engine account or your One account is compromised, an attacker could act through it.
  • Other software running as your user on the same computer can read Orchy's files.

8. Report a vulnerability

Please report security problems privately, not in public: email security@withone.ai.

Please give us a reasonable time to fix the problem before you disclose it. Don't access other people's data, disrupt the service, or test against systems that aren't yours. We won't pursue legal action against good-faith research that follows these rules.

We aim to reply within 5 business days.

Our machine-readable contact file is at /.well-known/security.txt.
