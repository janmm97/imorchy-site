Security

Last updated: 11 November 2026 · Version 1.0

Orchy comes two ways: the desktop app, which runs on your own computer, and hosted Orchy, which runs on our server in Canada. This page explains what we protect in each, where the limits are, and how to report a security problem.

We hold no security certifications (such as SOC 2 or ISO 27001). This page describes what the software and our server do, not an audit.

1. The desktop app

  • The Orchy app runs on your computer. Its dashboard listens only on your own machine (127.0.0.1), so other devices on your network can't open it.
  • The app does not send your tasks, files, keys or logs to us. There is no telemetry.
  • Data leaves your computer only when you connect a service yourself (your AI engine, a routing provider, One, voice providers, Cloudflare). It goes straight from your computer to that service, under your own account. One (withone.ai) is run by our own company, One Systems, Inc.

Who can control your desktop Orchy

  • Paired browsers only. A browser must be paired with a one-time code before it can change anything. Any change request must come from a paired browser and carry that browser's key.
  • Approval gate. Orchy asks you to approve before an agent sends, posts or deletes something. Some actions in connected apps may not ask first, so check what your agents can reach.
  • Separate accounts. Each workspace uses its own logins for connected apps. Accounts are never mixed between workspaces.

Secrets on your computer

  • The API keys you enter are stored in a settings file (.env) on your computer. They are not encrypted by Orchy. Protect your computer with a login password and disk encryption.
  • Login tokens for remote tool servers (MCP) are stored in a file only your user account can read.

Client pages (optional). If you turn on client pages, they run on a separate port and are reached through Cloudflare Tunnel, with Cloudflare Access checking each visitor's identity first. The main dashboard is never exposed this way.

2. Hosted Orchy

Hosted Orchy runs on our server at OVHcloud in Beauharnois, Canada. We list only measures we can show are in place:

  • Each customer has its own container on our server; access passes an authentication check before it reaches the container.
  • Web traffic reaches our server only through a Cloudflare Tunnel. The server's firewall admits nothing else from the internet except administrative access, which is by key-only SSH with password and root login turned off.
  • Sign-in is by Google or a one-time email link. Sessions use a random value of which only a hash is stored; the cookie is HttpOnly and Secure and lasts 30 days.
  • Your own AI-provider key is sealed with AES-256-GCM, using a key derived from a server-side secret that is separate for each customer.
  • Backups are encrypted (with the open-source tool age) before upload to Cloudflare R2; copies older than 14 days are removed.
  • Connections to the service use HTTPS. Encryption in transit ends at Cloudflare's edge, and traffic is carried to our server over the Cloudflare Tunnel.
  • The run log for connected apps keeps no message bodies and is kept for 90 days.
  • Each customer's agents run as a separate unprivileged user with no system privileges.
  • A customer's container cannot reach the server itself or private networks.
  • Each sign-in cookie is limited to its own address (our app and each customer's Orchy get separate host-only cookies), and every signed-in change needs an anti-forgery token and must come from Orchy's own page (the browser's Origin is checked).
  • A customer's Orchy won't open until the current Terms are accepted.

Our Data Processing Agreement (Annex 2) lists the same measures, and the Data Privacy page lists the companies that help us run the service.

3. Our website

  • imorchy.dev is served over HTTPS only. Plain HTTP requests, and requests to www.imorchy.dev, are redirected to https://imorchy.dev, and browsers are told to use HTTPS for imorchy.dev for a year (HSTS).
  • A strict Content Security Policy lets pages load code only from imorchy.dev. The one exception is a 3D graphics library loaded from jsDelivr on the home page.
  • The website sets no cookies, shows no challenge page and runs no analytics. (Hosted Orchy uses the sign-in cookies described in section 2.)
  • Other protections: no framing by other sites, no MIME sniffing, a strict referrer policy, and camera, microphone and location access turned off.

4. How we build Orchy

  • Every change goes through a pull request.
  • Automated tests run on each pull request, on Windows, macOS and Linux.

5. Known limits

We'd rather be clear about what Orchy can't protect against:

  • On the desktop, the approval gate is a filter, not a sandbox. Agents run with your user account's permissions, and other software running as your user can read Orchy's files.
  • If your AI engine account or your One account is compromised, an attacker could act through it.
  • In hosted Orchy, live data on our server is protected by the measures in section 2; we don't claim it is encrypted at rest.

6. Report a vulnerability

Please report security problems privately, not in a public issue:

  • Email: support@imorchy.dev

We aim to reply within 5 business days.

We won't pursue good-faith research that follows this page. That means: test only your own account and Orchy; stop and tell us once you reach anyone else's data; no denial of service, spam or social engineering; give us 90 days before going public.

Our machine-readable contact file is at /.well-known/security.txt.
